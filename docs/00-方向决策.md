# 选品洞察产品：方向决策

状态：待拍板 · 基于 5 份调研（P01 / P02 / P03 / P10 / P41）

## 0. 结论先行

**推荐方向：选品尽调 Agent（Pre-launch Due Diligence）。**

把选品从「预测哪个会爆」改成「在花钱之前，证明或证伪这个候选品」。核心产出不是数据面板，而是一份**带证据的决策备忘录**：能不能上、最可能怎么死、如果上该从哪里切。

产品骨架用 P01 的硬性筛除 + 利润公式，差异化内核用 P02 的评论缺陷归因，V1 用 P41 的监控做留存。P03（GEO）和 P10（关键词图谱）属于流量阶段，本产品暂不做。

一句话定位：

> 上架前，帮你砍掉会亏钱的品；剩下的品，告诉你从哪里切。

## 1. 五份调研的合并视图

| 项目 | 所属环节 | 痛点 | 难度 | 真实数据可得性 | 在本产品中的角色 |
|---|---|---|---|---|---|
| P01 多源选品评分 | 选品决策 | 3.6 | 2.2 | ❌ 销量拿不到 | **骨架**：硬性否决、利润公式、排序 |
| P02 评论缺陷挖掘 | 选品 / 改良 | 4.2 | 2.0 | ✅ Amazon Reviews 2023 | **内核**：发现切入机会，输出证据 |
| P41 竞品情报监控 | 竞争监控 | 3.6 | 2.5 | ⚠️ 受合规约束 | **V1 留存**：候选池持续跟踪 |
| P03 GEO 可见度 | 流量获取 | 3.8 | 中 | ✅ 官方 API | 邻接，暂不做 |
| P10 关键词图谱 | 广告投放 | 3.7 | 2.3 | ⚠️ 无转化数据 | 邻接，暂不做 |

读出来的关键事实：

1. **五份里唯一「痛点最高 + 数据真实可得 + 能做出干净的量化提升」的是 P02。**
2. P01 是选品流程的正确骨架，但它的天花板写在文档第一行：难点是数据不是算法，新玩家打不过卖数据的老工具。
3. 把两者叠起来的交集，正好是一个现有工具没覆盖的位置：**不卖数据估计，卖「上架前的风险排除 + 切入角度 + 证据」。**

## 2. 市场空位

现有工具（Helium10、Jungle Scout、卖家精灵）卖的是**数据估计**：搜索量、预估销量、BSR、关键词。它们是护城河很深的数据生意，新玩家正面打不过；而且预估销量本身误差大，卖家并不完全信。

卖家的真实决策不是「再给我一些数字」，而是：

- 这个品到底能不能上？
- 如果亏，最可能亏在哪？
- 如果做，我凭什么从现有竞品手里抢到份额？

| 维度 | 现有选品工具 | 本产品 |
|---|---|---|
| 输入 | 关键词 / 类目 | 候选品 + 卖家的成本与目标 |
| 输出 | 指标列表 / 排行榜 | 结论 + 否决项 + 证据 + 放弃条件 |
| 核心能力 | 数据估计 | 风险排除 + 切入角度 |
| 交互 | 看板，人自己综合 | Agent 追问，直接出结论 |
| 数据 | 平台数据（自建或付费） | 公开评论 / 法规 / 费用 + 用户提供的数据 |
| 态度 | 不告诉你别做 | 明确说「别做」 |

差异化的资产不是数据量，而是三样：

1. **否决规则库**：合规、毛利、体积重、侵权、认证，覆盖 76% 的失败原因。
2. **缺陷 → 机会的归因链**：从竞品差评直接推出「你该做什么」。
3. **决策结果回流**：被否决的品后来怎样、采纳的建议有没有效。

## 3. 产品定义

**目标用户**：1–3 人的跨境小团队 / 中小卖家的选品负责人。不是大卖——大卖已有工具和数据团队，也更愿意自己搭。

**使用场景**：

- 季度选品会前，手里有一批候选，需要在会上给结论而不是给数字。
- 刷到一个趋势品，想在 48 小时内判断要不要打样。

**输入**：

- 必填：品类 / 关键词，或竞品 ASIN / 链接
- 选填：目标售价、采购成本、目标市场、物流方式

**输出（一页决策备忘录）**：

1. **结论**：可做 / 有条件可做 / 不建议。必须明确，不许「综合来看有潜力」。
2. **否决项**：合规、毛利、体积重、侵权、认证。触发即出局，逐条附依据。
3. **机会点**：同类竞品评论里的 Top 缺陷，对应你能做的差异，引用 3 条原文作证据。
4. **竞争结构**：集中度、新品存活率、价格带。不用「竞品数量」这种糊弄指标。
5. **利润测算**：确定性公式逐项列出，每项标注来源（用户输入 / 公开数据 / 假设）。
6. **放弃条件**：打样后或上架 30 天后，出现什么就撤。
7. **待确认清单**：系统不知道、必须人去问供应商或查证的事。

第 7 条和「假设」标注不是免责声明，是产品的一部分。**明确说出不知道什么，是这类报告唯一能建立信任的方式。**

**能力边界（写进产品承诺里）**：

- 不预测销量。用评论增长、排名等代理信号，且明确标注是代理。
- 不做自动上架、自动改价、自动跟卖。
- 不采集个人信息，不绕反爬，不做高频抓取。
- 合规只给「需核查 + 依据」，不给法律意见。

## 4. 为什么这个方向成立

1. **痛点结构对齐。** 调研里 76% 的失败来自合规、竞争恶化、利润算错、需求判断错——全是现有工具不覆盖的维度。我们不是做得更准，是做他们没做的部分。
2. **数据可行。** 评论、法规、平台费用、趋势都是公开的，不需要平台内部数据。销量不确定就承认不确定，反而成为可信度来源。
3. **飞轮可验证。** 「被否决的品后来是否真的失败」「建议的切入角度是否被采纳」都能回流。数据工具没有这个回路，越用越同质；我们有。

## 5. 候选方向对比

| 方向 | 内容 | 优势 | 问题 | 结论 |
|---|---|---|---|---|
| **A. 选品尽调 Agent** | 否决 + 评分 + 缺陷机会 + 监控 | 覆盖完整决策链，叙事清楚，数据可行 | 范围大，需严格切 MVP | ✅ **主线** |
| B. 纯评论改良引擎 | 只做 P02 | 数据最好、技术最干净、最快出结果 | 用户是谁？更像一次性咨询，难标准化，不是「选品」 | 作为 A 的首发模块 |
| C. GEO 可见度 | P03 | 前沿、成本低、故事好听 | 与选品无关，测量方法不成熟，效果无法承诺 | 暂缓，后期可做获客内容 |
| D. 关键词图谱 | P10 | 技术轻、有可视化 | 服务于广告，不是选品，且缺转化数据 | 暂缓 |

## 6. MVP 范围（建议 4 周）

**Week 1｜内核**
- 选 1 个市场（建议美国）+ 2 个类目（建议 3C 配件、家居）
- Amazon Reviews 2023 取数、清洗、语言过滤
- 通用 Embedding + 聚类基线 → 受控标签体系 → LLM 归因 + 证据引用
- 产出：能跑通的「缺陷机会」分析

**Week 2｜骨架**
- 硬性筛除规则库（3 个类目的认证 / 禁限售 / 侵权要点）
- 利润测算公式（用户输入 + 公开费率）
- 备忘录生成器：结论、否决项、机会点、假设标注、放弃条件

**Week 3｜验证**
- 用历史评论做时间切分回测：T1 的缺陷信号，T2 是否真的持续
- 自己跑 3 个真实类目的完整备忘录；能约到卖家访谈更好
- 产出：backtest 结果 + 3 份备忘录

**Week 4｜内测**
- 找 3–5 位测试者（同行或卖家）看备忘录，记录他们会不会用、为什么
- 定下结果回流表结构（品、结论、建议、三个月后表现）

**MVP 不做**：多语言、多平台、实时监控、自动采集、账号与付费。

## 7. 关键风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 数据合规与可持续 | 爬平台不可持续，也可能违法 | 验证期用公开数据集；生产期用用户提供的数据 + 官方 API + 公开网页，明确边界 |
| 用户不愿给数据 | 没有成本售价，利润测算做不了 | 先交付「公开信息也能给 60% 价值」的报告，剩余靠提问补全 |
| 结论可信度 | LLM 容易编 | 结论必须带来源或计算过程；利润用公式；不确定显式标注 |
| 市场教育 | 卖家习惯看数字，不习惯看否决 | 用 backtest 展示「被我们砍掉的品后来怎样」 |
| 大厂跟进 | 工具加一个「风险诊断」按钮 | 护城河在规则库和结果数据，不在模型 |

## 8. 已拍板（2026-11-22）

| 决策 | 结论 | 影响 |
|---|---|---|
| 产品形态 | 先做 MVP 看效果，长期做中小卖家 SaaS | v0 不接账号和计费，但模块边界按 SaaS 留口 |

| 数据条件 | 暂无卖家与店铺数据，只有公开数据集 | 验证改为公开数据回测；利润改用反向测算 |
