# P01 多源选品评分与蓝海挖掘

评级：✅ P2（痛点 3.6 / 难度 2.2） | 层级：L1 | 实施角色：算法 数据
技术钩子：多因子排序模型、特征工程、LightGBM、榜单评测
目标客户：B2C 平台卖家、全托管供应商、品牌方
定位：入门项目。技术不炫，但它是理解"跨境生意怎么开始"的最佳切入点，也是特征工程的好练手场。适合作为第一个项目，或作为其他项目的数据基础。

⚠️ 先说清楚这个项目的天花板：选品的真正难点不是算法，是数据。真实的选品工具（Helium10、卖家精灵、Jungle Scout）核心竞争力是数据源，不是模型。团队做这个项目，核心看的是特征工程和排序建模能力，不要宣称"我做了个比卖家精灵更好的选品工具"。

## 1. 业务场景

### 1.1 场景还原

星辰科技（B1 §4.1）每季度要上 30–50 个新品。运营总监老王的选品流程是这样的：

```text
① 刷榜单：看亚马逊 Best Sellers、New Releases、Movers & Shakers
② 看竞品：看几个对标店铺最近上了什么
③ 用工具：查一下月搜索量、竞争度、预估销量
④ 算利润：估个出厂价，算 FBA 费、佣金、广告，看毛利够不够
⑤ 拍脑袋：凭经验判断"这个能做"
```

问题出在第 ⑤ 步。

星辰 2025 年选了 42 个新品，一年后结果是：

| 结果 | 数量 | 占比 |
|---|---|---|
| 成为主力款（月销 > 500） | 5 | 12% |
| 能跑量但利润薄 | 11 | 26% |
| 勉强保本 | 9 | 21% |
| 亏钱清仓 | 17 | 40% |

40% 的失败率，每个失败款平均压 8–15 万的货。 一年因为选品失误的损失约 150–200 万。

### 1.2 失败的真正原因

老王复盘了那 17 个失败款，发现失败原因分布是这样的：

| 失败原因 | 数量 | 说明 |
|---|---|---|
| 合规问题 | 4 | 认证成本超预期、或需要 EPR 注册没算进去 |
| 竞争恶化 | 5 | 上架时竞品少，3 个月后涌入十几家打价格战 |
| 利润算错 | 4 | 漏算了退货损耗、旺季仓储费翻倍、汇率变动 |
| 需求判断错 | 3 | 榜单热度是短期爆点，不是持续需求 |
| 供应链问题 | 1 | 供应商产能不稳定 |

⭐ 这张表是本项目的核心洞察：选品失败很少是因为"没看销量数据"，而是因为只看了销量数据。

合规、竞争趋势、真实利润、需求持续性 —— 这四个维度在大多数选品流程里是缺失的，而它们贡献了 76% 的失败。

### 1.3 这个痛点值多少钱

| 收益项 | 测算逻辑 | 年化 |
|---|---|---|
| 降低选品失败率 | 失败率从 40% 降到 30%，减少 4 个失败款 × 平均压货损失 10 万 | 约 40 万 |
| 提前排除合规雷 | 4 个合规问题款，若提前发现可避免全部投入 | 约 30 万 |
| 减少选品调研工时 | 2 人 × 每周 1 天 × 50 周 | 约 8 万 |
| 合计 | 约 78 万 |  |

⚠️ 测算，非实测。而且这个项目的收益上限受数据质量限制——如果数据源不准，评分再精也没用。

## 2. 痛点量化

| 维度 | 内容 |
|---|---|
| 业务对象 | 候选商品、品类、竞品、供应商 |
| 使用角色 | 执行：选品专员/运营；决策：运营总监、老板 |
| 触发条件 | 季度选品会、发现新趋势、竞品上新 |
| 当前流程 | 刷榜单 → 查工具 → Excel 算利润 → 会上讨论 → 拍板 |
| 输入输出 | 输入：品类/关键词；输出：候选清单 + 评分 + 决策依据 |
| 频率与规模 | 每季度筛选数百个候选，最终上 30–50 个 |
| 时间与成本 | 单个候选深度调研 2–4 小时；大部分候选只做了浅层判断 |
| 错误与损失 | 失败率 40%，单次失败压货 8–15 万 |
| 根本原因 | 维度缺失（只看销量不看合规/竞争趋势/真实利润） |
| 数据条件 | ⚠️ 这是本项目最大的约束，见 §5 |
| 决策性质 | 多因子评分 + 排序，属于"辅助决策" |
| 风险等级 | 中（决策金额大，必须人工拍板） |
| 目标指标 | 排序质量（NDCG）、失败率下降、决策效率 |

## 3. 为什么这是一个 AI 问题（以及为什么部分不是）

### 3.1 拆开看：哪些环节需要模型，哪些不需要

| 环节 | 用什么 | 为什么 |
|---|---|---|
| 数据采集与清洗 | 数据工程 | 不是 AI 问题，是 ETL |
| 利润测算 | 确定性公式 | ⭐ 绝对不能用模型，价格算错就是钱 |
| 合规风险筛查 | 规则库 + 检索 | 法规是明确的，用 RAG 而非预测 |
| 需求趋势判断 | 时序 + 统计 | 判断是短期爆点还是持续需求 |
| 竞争强度评估 | 特征工程 | 集中度、评论数分布、价格带 |
| 综合排序 | 排序模型（LTR） | ⭐ 这里才是机器学习的用武之地 |
| 最终决策 | 人 | 金额大、不可逆 |

特别注意利润测算那一行——这和 P13（智能报价）是同一个道理：涉及金额计算的地方必须用确定性公式。

### 3.2 排除更简单的方案

| 备选 | 能不能解决 | 不够在哪 |
|---|---|---|
| 直接用现成选品工具 | ⚠️ 部分 | 工具给的是单维度数据，不给综合判断；且缺合规和真实利润维度 |
| Excel 加权打分 | ⚠️ 部分 | 权重靠拍脑袋，无法从历史结果学习 |
| 只看销量排序 | ❌ | 正是失败的原因（见 §1.2） |
| 大模型直接推荐选品 | ❌ | 它没有实时市场数据，会编造销量数字 |

⚠️ 最后一条很重要。 很多人的第一反应是"让 GPT 推荐选品"。这是错的——大模型没有实时的市场数据，它给出的销量、竞争度数字都是编的。它能做的是辅助分析已有数据，不是提供数据。

## 4. 目标流程

```text
① 候选池构建
榜单数据 + 关键词扩展 + 竞品上新 + 趋势数据
↓
② 数据补全
搜索热度 / 竞品数量 / 价格带 / 评论数 / 上架时间分布
↓
③ 硬性筛除（规则，不打分）        ← ⭐ 先排除，再排序
❌ 禁限售品类
❌ 需要高成本认证且成本 > 阈值
❌ 明显侵权风险（大牌专利/商标）
❌ 毛利率 < 底线
❌ 体积重量超 FBA 经济区间
↓
④ 特征工程（六个维度）
市场规模 / 需求趋势 / 竞争强度 / 利润空间 / 合规成本 / 供应链可得性
↓
⑤ 利润测算（确定性公式）
出厂价 + 头程 + 关税 + 佣金 + FBA + 广告预估 + 退货损耗 → 净利率
↓
⑥ 综合排序（LTR 模型 或 加权评分）
↓
⑦ 输出候选清单 + 每项的分维度得分 + 风险提示
↓
⑧ 人工评审与决策          ← ⭐ 必须人工
↓
⑨ 记录决策与结果           ← ⭐ 这是模型能持续改进的唯一来源
（选了/没选、上架后表现如何）
```

### 4.1 ⭐ 为什么"先硬性筛除再排序"

这是一个容易做错的设计。

```text
❌ 错误做法：把合规风险作为一个负分项加入总分
→ 结果：一个高销量但需要 20 万认证费的产品，
可能因为销量分很高而排在前面

✅ 正确做法：硬性条件先做筛除（binary），通过的才进入排序
→ 合规不过关的，不管销量多好都不进候选池
```

## 5. ⚠️ 数据方案（本项目最大的约束）

### 5.1 诚实面对：团队拿不到真实选品数据

真实的选品工具依赖：

平台内部数据（ABA 关键词报告等）

大规模爬取的商品与销量估算

付费数据源

这些数据团队通常都没有，而且不该去爬。

### 5.2 可行的数据方案

| 方案 | 数据来源 | 能做什么 | 局限 |
|---|---|---|---|
| A. 公开电商数据集 | Amazon Reviews 2023 的商品元数据（含类目、价格、评论数、时间）、各类 Kaggle 电商数据集 | ✅ 真实的商品/价格/评论分布
✅ 可做竞争强度、需求趋势特征 | ❌ 没有销量数据 |
| B. 趋势数据 | Google Trends 公开 API、UN Comtrade 贸易统计 | ✅ 真实的需求趋势信号 | 粒度粗 |
| C. 合规数据 | 各国公开法规、HS 编码、认证要求 | ✅ 真实的合规规则库 | 需整理 |
| D. 销量代理指标 | 用评论数增长率作为销量的代理变量 | ✅ 学术界常用做法 | ⚠️ 是代理不是真值，必须说明 |
| E. 合成补全 | 用规则+分布拟合生成销量、成本数据 | 补齐缺失字段 | ⚠️ 必须标注为合成 |

推荐组合：A + B + C + D，销量用评论数代理，并在文档里明确说明这是代理指标。

### 5.3 ⭐ 标签怎么来（排序模型的关键问题）

排序模型需要"哪个商品更好"的标签，这从哪来？

三种做法，可信度递减：

| 方案 | 做法 | 可信度 |
|---|---|---|
| A. 用后验表现构造标签 ⭐ | 用数据集里靠后时间段的实际表现（评论增长、评分维持）作为标签，用靠前时间段的特征做输入 | ✅ 最可信，是真正的预测任务 |
| B. 人工标注偏好对 | 自己判断"A 比 B 更值得做"，构造 pairwise 标签 | ⚠️ 主观，但可用作补充 |
| C. 规则生成标签 | 用加权公式算出分数当标签 | ❌ 循环论证，模型只是在学你的公式 |

⭐ 方案 A 是这个项目的技术亮点。

把数据按时间切分：用 T1 时刻的特征，预测 T2 时刻的表现。这是一个真正的时序预测任务，而不是拟合一个人造分数。

### 5.4 合规声明

| 项目 | 状态 |
|---|---|
| 数据来源 | 公开数据集 + 公开 API + 公开法规 |
| 是否爬取平台 | ❌ 无 |
| 销量数据 | ⚠️ 用评论数作代理，非真实销量，已在文档中说明 |
| 部分字段 | ⚠️ 合成补全，已标注 |

## 6. 特征工程（本项目的核心技术内容）

### 6.1 六维特征设计

| 维度 | 特征示例 | 数据来源 |
|---|---|---|
| 市场规模 | 类目商品总数、价格带分布、评论总量 | 公开数据集 |
| 需求趋势 | 搜索热度斜率、季节性强度、是否短期爆点 | Google Trends |
| 竞争强度 | ⭐ 评论数基尼系数（集中度）、Top10 份额、新品占比、价格离散度 | 公开数据集 |
| 利润空间 | 售价中位数、估算成本、预估净利率 | 计算 |
| 合规成本 | 是否需认证、EPR 类目、预估认证费 | 法规库 |
| 供应链 | 类目 1688 供应商数量代理、起订量 | 公开信息/合成 |

### 6.2 ⭐ 三个值得深挖的特征

① 竞争集中度（基尼系数）

```text
同样是 100 个竞品：
情况 A：Top3 占 80% 评论  → 高度集中，新手很难挤进去
情况 B：评论均匀分布      → 分散市场，有机会

→ 光看"竞品数量"分不出这两种情况，必须看分布
```

② 需求持续性（区分爆点和真需求）

```text
特征：搜索热度的
- 斜率（是在涨还是在跌）
- 波动率（是稳定需求还是脉冲）
- 季节性分解后的趋势项
- 历史峰值衰减速度   ← ⭐ 关键：爆点会快速衰减
```

③ 新品存活率

```text
该类目里，最近 6 个月上架的商品中，
有多少还在持续获得评论？

→ 高存活率 = 新进入者有机会
→ 低存活率 = 老玩家垄断，新品进不去
```

## 7. 模型与评测

### 7.1 实验设计

| 编号 | 方案 | 说明 |
|---|---|---|
| B0 | 随机排序 | 下界 |
| B1 | 按销量代理指标排序 | ⭐ 主基线（这是行业现状） |
| B2 | 人工加权评分 | 模拟运营的经验做法 |
| E1 | LightGBM 回归（预测后验表现） |  |
| E2 | LambdaMART（Learning to Rank） | 直接优化排序 |
| E3 | E2 + 六维特征全量 |  |
| E4 | E3 + 硬性筛除前置 | 完整方案 |

### 7.2 评测指标

| 指标 | 说明 |
|---|---|
| NDCG@K | ⭐ 主指标，排序质量 |
| Precision@K | Top-K 中真正表现好的比例 |
| 对比 B1 的提升 | ⭐ 关键——比"只看销量"好多少 |
| 硬性筛除的召回率 | 该排除的有没有排除掉 |
| 特征重要性 | 哪些维度真正有预测力 |

### 7.3 消融要点

| 消融项 | 要回答的问题 |
|---|---|
| 逐个去掉六个维度 | 哪个维度贡献最大？（预期：竞争强度和趋势 > 市场规模） |
| 有/无硬性筛除 | 前置筛除对 Top-K 质量的影响 |
| 时间切分窗口 | T1→T2 间隔多久预测最有效 |
| 模型类型 | 回归 vs LTR 哪个更适合 |

⭐ 特征重要性分析是这个项目最有意思的产出。 如果你的实验发现"竞争集中度比市场规模更有预测力"，这就是一个有业务价值的实证发现。

## 8. 里程碑（1.5–2 周）

### Day 1–3：数据与基线

```text
□ 获取公开电商数据集，选 2–3 个类目
□ 数据探查：价格、评论、时间分布
□ 时间切分（T1 特征期 / T2 表现期）
□ 构造后验表现标签
□ 跑通基线 B1（按销量代理排序）
产出：数据集 + 基线 NDCG
```

### Day 4–7：特征工程

```text
□ 实现六维特征
□ 重点实现三个深度特征（基尼系数、需求持续性、新品存活率）
□ 整理合规规则库（至少覆盖 3 个类目的认证要求）
□ 实现利润测算公式（确定性）
产出：完整特征表 + 规则库
```

### Week 2：模型与分析

```text
□ 训练 LightGBM 回归 → E1
□ 训练 LambdaMART → E2
□ 加入全量特征 → E3
□ 前置硬性筛除 → E4
□ 消融实验（逐维度）
□ 特征重要性分析
□ 简单看板输出候选清单
产出：完整对比表 + 特征重要性报告
```

### 差异化分支

| 分支 | 方向 |
|---|---|
| 特征工程 | 深挖竞争强度刻画、需求持续性建模 |
| 排序算法 | 对比不同 LTR 方法（Pointwise/Pairwise/Listwise） |
| 合规维度 | 把合规做深，接 RAG（可与 P27 联动） |
| 品类 | 换品类，分析品类间的规律差异 |
| 可解释性 | SHAP 分析，输出"为什么推荐这个品" |

## 10. 常见坑

| # | 坑 | 避免方法 |
|---|---|---|
| 1 | 用加权公式生成标签 | 循环论证，改用时间切分的后验表现 |
| 2 | 不说明销量是代理指标 | 明确标注 |
| 3 | 合规做成打分项 | 改为硬性筛除 |
| 4 | 用模型算利润 | 用确定性公式 |
| 5 | 只用"竞品数量"刻画竞争 | 加集中度、价格离散度等分布特征 |
| 6 | 没有 B1 基线（按销量排序） | 必须有，否则无法证明价值 |
| 7 | 时间切分有泄漏 | 严格确保 T2 信息不进入 T1 特征 |
| 8 | 宣称超越商用工具 | 诚实说明数据源差距 |
