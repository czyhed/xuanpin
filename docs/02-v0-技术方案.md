# v0 技术方案（P01 骨架 + P02 内核）

**P01 负责否决**：用硬规则和确定性算式，先判断这个品「能不能做、值不值得做」——合规不过、算不过账、竞争没位置，就出局。

**P02 负责破局**：只对活下来的品，从评论里挖出「可修复、持续、有原文证据」的切入机会，回答「如果做，从哪切」。

状态：可执行 · 2026-11-22 · 基于数据可行性、P02 技术、P01 商业三份专项调研

上游文档：[00-方向决策.md](00-方向决策.md) · [01-MVP-v0.md](01-MVP-v0.md) · [原始调研](research/)

## 0. 一页结论

| 决策 | 结论 | 依据 |
|---|---|---|
| 数据集 | Amazon Reviews 2023 · Appliances，抽样 100 万条 | 2023 版没有 50–200 万评论的 3C 类目；Appliances 210 万，体量合适，缺陷类型丰富 |
| 产品定位 | 再收窄：不是「再给一份报告」，是「你的数字 + 硬否决 + 原文证据 + 放弃条件」 | 亚马逊 2026-08 上线免费 Validate Product Idea（待核实） |
| 利润 | 修正为「采购价上限 + 到岸成本」两个数 | 原公式把采购价上限误标成到岸成本，税基和退货口径也有错 |
| 竞争指标 | 近 12 个月窗口的 Top10 份额 + Gini + 新品评论份额 + 队列存活 | 生命周期累计会被老品年龄系统性放大 |
| 缺陷引擎 | `bge-small-en-v1.5` + MiniBatchKMeans 主链路，HDBSCAN 做长尾对照 | 纯 CPU 可跑，确定、可复现；长尾能力用对照实验验证，不预设 |
| 归因 | 簇级调用 `claude-opus-5-5`，结构化 JSON 输出，强制证据引用 | 全量一次约 $4–6，成本不是瓶颈；证据一致性优先 |
| 周期 | 2 周跑通端到端 demo | 数据 11 分钟可下载，模块边界清晰 |

v0 仍然只证明三件事：否决能落地、竞争结构能算清、缺陷机会能挖出来，最后压成一页可执行的备忘录。

## 1. 定位修正

商业调研的结论是：空位真实，但窄。

- 现有工具卖全栈数据（Helium 10、Jungle Scout、卖家精灵，约 $39–279/月）或价格历史（Keepa，约 €19/月），都已被覆盖。
- 亚马逊 2026 年 8 月上线免费的「Validate Product Idea」，直接给市场、竞争、需求报告（**待核实**）。
- 因此付费价值不能是「更多数据」或「另一份报告」，只能是亚马逊给不了的四样：

1. **卖家自己的数字**：目标售价、采购报价、毛利要求。
2. **硬性否决**：合规、认证、利润、体积重，触发即出局。
3. **原文证据**：缺陷机会必须引用真实评论，不给结论裸奔。
4. **放弃条件**：什么指标、什么窗口、出现什么就撤。

演示和文案都按这四样讲，不再讲「比卖家精灵更准」。

## 2. 数据方案

### 2.1 主数据集

| 项 | 内容 |
|---|---|
| 来源 | HuggingFace `McAuley-Lab/Amazon-Reviews-2023` |
| 类目 | Appliances：评论 210 万 / 商品 9.43 万 |
| 时间 | 1996-05 至 2023-09 |
| 字段 | 评论：rating、title、text、images、asin、parent_asin、user_id、timestamp、helpful_vote、verified_purchase；元数据：main_category、title、average_rating、rating_number、features、description、price、store、categories、details |
| 体积 | 原始 gz 约 321 MiB；解压约 1.13 GiB；Parquet 约 0.4 GiB |
| 抽样 | 评论随机抽 100 万条，再取 rating≤3 做主分析（预计 25–35 万条） |
| 许可 | HF 卡无 license 字段；二手资料称 CC BY-NC 4.0（非商用），**待核实**。v0 仅内部研究，商用前书面确认 |

为什么不是 3C：2023 版 Cell_Phones 有 2080 万条，Home_and_Kitchen 6740 万条，下载和解压都超出 v0 的迭代节奏；Appliances 的家电缺陷（漏水、噪音、寿命、安装）同样能验证缺陷引擎。类目在配置里可换。

3C 备选（不进 v0 主路径）：

- Amazon Reviews 2018 5-core Cell_Phones_and_Accessories，112.8 万条，量级正好，但直链超时、可用性**待核实**。
- 从 Cell_Phones 流式筛子类，gz 2.53 GB、解压 9.34 GB，磁盘可承受但耗时长。

### 2.2 下载与处理

```text
HF_ENDPOINT=https://hf-mirror.com
hf_hub_download(repo_type="dataset", repo_id="McAuley-Lab/Amazon-Reviews-2023",
                filename="raw/review_categories/Appliances.jsonl")
hf_hub_download(..., filename="raw/meta_categories/meta_Appliances.jsonl")
```

处理顺序：

1. 校验字节数（调研实测 929,451,412 / 285,298,475），断点续传。
2. 流式解析，字符串转数值：`rating` → float，`timestamp` 毫秒 → 秒，`images` 二次 JSON 解析。
3. 按 `parent_asin` 关联评论与元数据。
4. 去重键：`(asin, user_id, timestamp, text_hash)`。
5. 语言识别（fastText `lid.176`），v0 只保留英文。
6. `text` 截断 256 token；保留 `review_id` 用于金标准排除。
7. 按年写 Parquet，中间结果全部落盘缓存。

### 2.3 字段映射

| 模块 | 可用字段 | 缺失与补法 |
|---|---|---|
| 竞争结构 | parent_asin、price、categories、rating_number、timestamp | 无销量、BSR、卖家数 → 评论份额与增速代理，显式标注 |
| 缺陷 | rating、title、text、timestamp、helpful_vote、verified_purchase | 无缺陷标签、批次、退货 → 聚类 + LLM + 200 条金标准；时间窗模拟批次 |
| 利润 | price（抓取时点） | 无采购价、头程、关税、广告、退货 → 反向公式 + 用户输入 |
| 否决 | title、features、description、details、categories | 无认证与专利信息 → 规则触发 + 用户清单，只给「需核查 + 依据」 |

### 2.4 数据边界

- 不爬平台，不采个人信息；展示时对 `user_id` 脱敏。
- `price` 是抓取时点价，不是实时价。
- 数据集截止 2023-09，v0 的所有结论都标注数据截止日；V1 必须接新数据。
- 原始调研里的 76% 失败率、40% 亏损率来自虚构案例，不得对外引用。

## 3. 系统结构

```text
输入：类目 / 子类目 / 竞品 ASIN + 目标售价与毛利（可选）
  ↓
硬性否决（规则）——任一触发即 no-go
  ↓
竞争结构（窗口指标）——集中度、新品份额、存活率、价格带
  ↓
利润测算（确定性公式）——采购价上限、到岸成本
  ↓
缺陷机会（聚类 + LLM）——频次、持续性、可修复性、证据
  ↓
结论整合——结论、否决项、待确认、放弃条件
  ↓
输出：一页决策备忘录
```

| 模块 | 输入 | 输出 | 约束 |
|---|---|---|---|
| `ingest` | HF 数据集 | 标准化评论/商品 Parquet | 幂等、可断点续传 |
| `features` | 清洗后数据 | 商品级特征表 | 时间切分严格，T2 不进 T1 |
| `compliance` | 商品属性 | 否决项 / 需确认项 | 只给依据，不给法律意见 |
| `competition` | 特征表 | 类目/子类竞争指标 | 全部标「评论代理」 |
| `economics` | 售价、毛利目标、费率表 | 采购价上限、到岸成本 | 确定性公式，不用模型 |
| `defects` | 负面评论 | 簇、标签、证据、持续性 | 证据必须原文 |
| `brief` | 上述结果 | Markdown/HTML 备忘录 | 结论必须可回溯 |
| `eval` | 金标准、回测 | 指标与错误分析 | 不报无基线结果 |

仓库结构沿用 `01` 的划分：

```text
src/selection/
  ingest/  features/  competition/  defects/
  economics/  compliance/  brief/  eval/  interfaces/
```

原则：core 不依赖 UI；每个模块输入输出有类型；所有外部调用可缓存，重复运行不重复花钱。

环境：Python 3.11（`uv` 建独立环境，3.13 的 torch 轮子待核实）；依赖 `sentence-transformers`、`scikit-learn`、`hdbscan`、`umap-learn`、`fasttext`、`pyarrow`。

以下按决策链排序：先 P01 规则，再 P02 缺陷，最后整合成备忘录。实施排期见 §7。

## 4. P01 骨架

P01 负责否决。顺序是先否决、再看结构、最后算账，避免为注定不能做的品投入分析。

### 4.1 合规否决

| 规则 | 触发 | 判定 |
|---|---|---|
| FCC Part 15 | 无线/射频 | 无 FCC ID 或 SDoC → 否决 |
| UN38.3 | 锂电池 | 无测试概要、MSDS、空运鉴定 → 否决 |
| CE + RoHS | 电子电气（欧盟） | 无 CE DoC / RoHS 报告 → 否决 |
| GPSR | 欧盟售、非欧盟制造商 | 无 EU 负责人与追溯信息 → 否决（2024-12-13 起） |
| WEEE / 包装 / 电池 EPR | 电子电气（欧盟） | 未注册 → 平台下架风险，需核查 |
| UL / ETL | 电源、充电器（美国） | 非联邦强制，平台事实必需 → 需核查 |
| Prop 65 | 加州售 | 可加警示；无方案 → 否决 |
| 平台限售 / 危险品 | 电池、激光等 | 无文件或未过 TIC → 否决 |
| 侵权 | 商标、专利 | 无检索结论 → 需核查 |

每条规则带 `source`、`effective`、`last_verified`。只给依据，不给法律意见；高风险转人工。

### 4.2 竞争结构

| 指标 | 计算 | 局限 |
|---|---|---|
| Top10 份额 | 近 12 个月 Top10 商品评论数 ÷ 窗口内总评论数 | 直观，阈值敏感 |
| Gini | 按窗口内评论份额算洛伦兹基尼 | 样本量和零膨胀敏感，不能跨类目比 |
| 新品评论份额 | 首评 <12 个月的商品评论数 ÷ 总评论数 | 首评不等于上架 |
| 队列存活率 | 首评 6 个月队列中，T2 仍有新评论的比例 | 只能看评论活跃，不是真实存活 |
| 价格带 | P10 / P50 / P90 + 变异系数 | 标价不等于成交价 |

v0 主指标用窗口 Top10 + Gini，辅以新品份额和队列存活。全部标「基于评论的代理指标」，不写成销量份额。

### 4.3 利润：输出两个数，不输出一个假净利率

变量：

- P 售价；c 佣金率；a 广告占比（TACOS）；r 退货率；l 单次退货损失 ÷ 售价；F FBA 配送费；f 头程 + 入仓；S 仓储；M 目标毛利额；d 关税率。

美国站（FOB 税基，国际运费不计入关税）：

> 采购价上限 = [P × (1 − c − a − r × l) − F − f − S − M] ÷ (1 + d)
>
> 到岸成本 = 采购价上限 × (1 + d) + f + S

欧盟站（CIF 税基，国际运费计入关税）：

> 采购价上限 = [P × (1 − c − a − r × l) − F − S − M] ÷ (1 + d) − f
>
> 到岸成本 = (采购价上限 + f) × (1 + d) + S

必须同时输出「采购价上限」和「到岸成本」，卖家拿供应商 FOB 报价或到岸报价对，不会拿错口径。关税按 HTS/TARIC 查，不设默认值；VAT 可抵扣，不算成本。

### 4.4 费率表

状态均为 2025 表 + 2026 变更，**执行前以卖家后台 Fee Preview 为准**。

| 项 | 数值 | 状态 |
|---|---|---|
| 佣金 | 电子配件 ≤$100 15%、>$100 部分 8%；消费电子 8%；家居 15%；最低 $0.30（2025-01-15） | 待核实 |
| 标准 FBA | 小标准 ≤2oz $3.06；大标准 ≤4oz $3.68；旺季 $3.25 / $3.92 | 2026-01-15 起平均 +$0.08，待核实 |
| 低价 FBA（<$10） | 小标准 $2.29 或 $2.43（两份调研不一致）；大标准 $2.91 | **冲突，必须查官方页** |
| 仓储 | $0.78/立方英尺/月（1–9 月）；$2.40（10–12 月） | 待核实 |
| 入库配置 | $0.21–0.44/件；2026 最小拆分 +$0.05/件；缺陷费 $0.60/件 | 待核实 |
| 退货 | 电子 8–12%；配件 3–5%（第三方数据） | 用用户输入覆盖 |
| 广告 | 电子 ACOS 20–30%（第三方） | 用 TACOS，不混用 ACOS |
| 关税 | 按 HTS 查 | 无默认值 |

运费按计费重取实重与体积重的较大值（体积重除数 139）。佣金按 Fee Preview，不按浏览类目猜。

## 5. P02 内核

P02 负责破局。只有通过 P01 的品才值得挖评论，否则会把分析成本花在注定不能做的品上。

### 5.1 选型

| 组件 | v0 选择 | 理由 | 升级路径 |
|---|---|---|---|
| Embedding | `bge-small-en-v1.5`（33M / 384 维 / MIT） | CPU 可行，英文够用，内存 <0.1 GB | 多语种触发后换 `multilingual-e5-small` 或 BGE-M3 |
| 聚类主链路 | MiniBatchKMeans，K=300–400，固定种子 | 100 万条下分钟级、可复现 | 数据增量或长尾需求上来再评估 HDBSCAN |
| 长尾对照 | 5 万分层样本：UMAP + HDBSCAN | 验证 KMeans 是否吞掉稀有缺陷 | 对照胜出才切换主链路 |
| 归因 | `claude-opus-5-5`，簇级调用 | 标签一致性和证据引用要求高 | 评测无损后再考虑 Sonnet 5.5 |
| 标签体系 | 8 域 × 3–4 叶类，约 28–30 类 | 可控、可统计、可追踪 | 新类须人工审批 |
| 存储 | Parquet + NumPy/FAISS（可选） | 40 万条向量约 0.6 GB，无需向量库 | 千万级再引入 |

**KMeans 的争议必须用实验解决。** P02 原文明确反对 K-Means（需预设 K、假设球形簇、长尾不友好）；技术调研则认为 v0 规模下 KMeans 更稳更快。方案不预设结论：主链路 KMeans，5 万样本 HDBSCAN 对照，用金标准召回和聚类纯度决定。安全缺陷单独走扫描通道，不依赖主链路。

### 5.2 流水线

1. **清洗**：HTML 反转义；去模板句（verified purchase / received free）；删 URL、邮箱；精确 + MinHash 近重复；英文过滤。
2. **过滤**：主分析取 rating≤3；4–5 星分层抽样只进评测，防止漏掉高星缺陷。
3. **编码**：bge-small，L2 归一化；可选 ONNX INT8。
4. **聚类**：MiniBatchKMeans，K=300–400，`n_init=3`，固定种子；质心余弦 ≥0.9 合并同缺陷多簇。
5. **长尾对照**：5 万样本，UMAP 5–10 维 + HDBSCAN（`min_cluster_size=25–50`，`min_samples=10`）；报告 10 次种子 ARI，噪声率目标 10–30%。
6. **噪声处理**：余弦 ≥0.5 二次归簇；残余进「安全 + 长尾」人工队列，不丢弃。
7. **归因**：每簇取 10–20 条代表评论（近质心与随机各半），一次 LLM 调用，同簇缓存。
8. **汇总**：按受控类别统计频次、月度序列、覆盖商品数，进入机会分。

### 5.3 受控标签体系

8 个域，约 28–30 个叶类：

- 功能性能：充电、连接、功率、兼容
- 结构耐久：开裂、松动、脱落、磨损
- 安全：过热、异味、漏电、材质
- 规格描述：尺寸、颜色材质、容量、夸大
- 使用：说明书、安装、操作
- 包装物流：破损、缺错件、延误、运输损坏
- 软件服务：App、固件、客服、保修
- 其他：预期落差、假冒、无法归类

每个类目在 YAML 中定义：code、定义、纳入/排除例、责任方、可修复先验、安全标记。版本冻结，改类必须走人工审批。

### 5.4 LLM 归因

输出严格 JSON：

```json
{
  "primary_category": "枚举值",
  "secondary_categories": ["枚举值"],
  "description": "≤40 词，只写现象",
  "evidence_ids": ["恰好 3 条，必须来自输入"],
  "confidence": 0.0,
  "proposed_new_category": null,
  "needs_human": false
}
```

实现要点：

- 用结构化输出（`output_config.format`）约束 schema，不用 assistant 预填。
- `evidence_ids` 必须逐字命中输入；不命中重试一次，仍失败转人工。
- `description` 禁止写出现率、因果和建议，只写现象。
- 新类只能进 `proposed_new_category`，人工审批后才进体系。
- 同簇只标一次并缓存；每 50 簇用 `claude-haiku-5-5` 复标一次，算一致率。
- `unclassified` 超过 15%，先改标签体系，不让 LLM 自由发挥。

### 5.5 缺陷机会分

机会分 = 频次、持续性、可修复性、证据强度的几何平均。几何平均防止某一项为 0 时总分归零；安全项不进机会排序，单独走风险通道。

| 因子 | 计算 | 说明 |
|---|---|---|
| 频次 | 缺陷提及数 ÷ 类目负面评论数，类目内分位归一 | 必须给分母 |
| 持续性 | 0.5 × 近 12 个月月份覆盖率 + 0.5 × 趋势斜率 | 回测只用 T1 |
| 可修复性 | LLM 按 rubric 给档位，不给美元数字 | 见下 |
| 证据强度 | 条数、不同商品数、不同月份数、原文具体性 | 防止单商品刷屏 |

可修复性 rubric：

| 档位 | 分值 | 含义 |
|---|---|---|
| 改文案/说明/软件/包装 | 1.0 | 不开模，周期短 |
| 换配件或小改结构 | 0.6 | 不开模 |
| 修模/换材料 | 0.3 | 有开模成本 |
| 新开模/换方案/涉认证 | 0.0 | 周期 >8 周 |
| unknown | 单列 | 不参与排序，转人工 |

### 5.6 评测

金标准 200 条：120 条 rating≤3、50 条 4 星、30 条 5 星；按商品、月份、长度分层。标注字段：是否含缺陷（是/否/存疑）、原文 span、主类（最多 3 个）、边界规则（物流 vs 产品、描述不符 vs 缺陷、用户失误不算）。

- 双人独立标注全部 200 条；若只能单人，至少 50 条找第二人交叉，报 Cohen's κ（目标 ≥0.6），并明确说明单人标注的局限。
- 金标准 review_id 从 few-shot、阈值调参和近重复中排除。
- 指标优先级：评论级覆盖召回 > 类别级召回 > 证据支持率 > 聚类纯度。
- 安全类单独看召回，目标 100% 进安全桶或人工队列。
- 基线必须跑：50 条关键词规则、随机簇、5 万样本 HDBSCAN。
- 回测：T1 取 2022-10 至 2023-06 共 9 个月，T2 取 2023-07 至 2023-09 共 3 个月；用 T1 持续性分与 T2 月份覆盖率算 Spearman，完整排序对比「按评论数排序」。

### 5.7 成本

| 项 | 估算 | 说明 |
|---|---|---|
| 编码 | CPU 1–6 小时 | 25–35 万条负面评论，256 token |
| 聚类 | 分钟级 | MiniBatchKMeans；HDBSCAN 对照 10–40 分钟 |
| 簇级归因 | 300–400 簇 × 1.5–2k 输入，约 0.6–0.8M input / 5–8 万 output | Opus 5.5：约 $3.4–4.8；加复标与重试约 $5–8 |
| 合计 | 现金 <$15，机时 <10 小时 | API 不是瓶颈 |

不按 OpenAI/Gemini 价格估算；默认 Claude Opus 5.5（$4 / $20 每百万 token）。Sonnet 5.5（$2 / $10）和 Haiku 5.5（$0.10 / $0.50）只作为「评测无损后」的降级实验，不默认使用。

### 5.8 v0 不做

| 不做 | 触发条件 |
|---|---|
| 微调 | 金标准召回 <70%，且错误主要是「同缺陷不同说法」的语义失败；有 ≥5k 干净对和 GPU |
| 难负例挖掘 | 微调已立项，且「话题同 / 缺陷异」探针仍混淆 |
| 增量聚类 | 日新增 > 全量 1–2%，或全量重聚类超过 SLA |
| 多语言 | 目标类目/站点非英文 ≥10–15% |
| 逐条 LLM 分类 | 始终不做；只对簇调用 |
| 向量数据库 | 千万级以下不做 |
| 严重度学习模型 | 没有严重度标签，继续用规则 + 权重 |

## 6. 结论与备忘录（整合层）

判定顺序：

1. 任一硬性否决 → no-go。
2. 重大「需确认」未闭环 → conditional。
3. 采购价上限 < 供应商报价 × 1.15 → no-go。
4. 存在低成本、持续、有 3 条证据的缺陷切口 → conditional 或 go。
5. 其余 → go。

备忘录七段：结论、否决项、竞争结构、利润测算、缺陷机会、放弃条件、待确认清单。P01（否决、竞争、利润）先于 P02（缺陷切口），与判定顺序一致。

放弃条件必须写成「指标 + 阈值 + 窗口 + 动作 + 负责人」，例如：

- 打样 FOB 报价 > 采购价上限，或打样到岸报价 > 到岸预算上限（采购价上限 × (1 + 关税) + 头程 + 仓储）→ 放弃。
- 上架 30 天周评论增速 < 5 条且 TACOS > 25% 连续 14 天 → 停止补货。
- 60 天退货率 > 12% → 停售复核。
- Top3 份额 90 天上升 10 个百分点 → 退出。

避免假精确：两位有效数字；给区间不给点值；广告 10/15/20%、退货 5/8/12% 做敏感性表；不合成单一总分；每个数字标「事实 / 公开费率 / 假设 / 代理」。

## 8. 成功标准

1. 缓存后端到端 10 分钟内产出备忘录。
2. 缺陷召回率（200 条金标准）≥70%，证据支持率 ≥80%。
3. 回测排序优于「按评论数排序」基线；至少 Precision@20 有提升。
4. 3 位测试者能说出「我会用 / 不会用，因为……」，至少 2 人愿意用其中一段。

第 4 条是产品判断，优先级高于任何模型指标。
